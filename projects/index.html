Coding with AI

Working projects I built with AI coding tools, several of them for Effective Coding with AI, a Carnegie Mellon course, and smaller apps and visualizations I coded with an AI assistant from my own data. Each project has its own page with screenshots, how I built it, and what it teaches, and each repo includes the prompts and build log. I use them as examples in class.

Browser game · October 2026

Monday, 8:55

JavaScript and one HTML canvas, no libraries, Claude Code

A game I inherited and finished. You are the doorman of an office building's revolving door in the five minutes before 9:00 on a Monday. Hold Space to push the door, hold an arrow key to make a line wait, and keep every rider at a speed they can stand: late managers hate a slow door, coffee interns spill on a fast one, and sooner or later they ride together. The idea, the spec and the first version came from another student in Effective Coding with AI, a Carnegie Mellon course. For the course's code handoff assignment I took over that repo, kept the original design, and built it out to the spec.

What it teaches

  • Read an inherited codebase and its spec before changing anything, and write down what is actually done.
  • Keep the original design when extending someone else's code: same classes, same names, new work beside the old.
  • Separate the rules from the drawing so tests and a simulated player can run the real game without a browser.
  • Tune difficulty with numbers from hundreds of simulated rounds, not from how one round felt.
  • Ask an AI what it changed. It made a rule change without asking, and only a direct question brought it out.

Web app · October 2026

Slide Finder

Python, FastAPI, Supabase Postgres with pgvector, Voyage AI embeddings, Claude Haiku (image descriptions and titles), Vercel, Claude Code

A technical project on one question: how do you match a question to a slide? Every slide I have taught since Fall 2023, across five courses, is indexed four ways in one vector database: what I said in class while it was on screen, an AI's description of its picture, the slide's own text and speaker notes, and plain keywords. Meaning and keyword matches are fused into one ranking, and every result shows which way found it and why. It is my own tool, not a student-facing one; I use it to pull old slides into new decks. Built for Effective Coding with AI (15-113), a Carnegie Mellon course, as the vector database project in Fall 2026.

What it teaches

  • Test retrieval with questions that share no words with the answer, so you measure meaning and not word overlap.
  • Store each kind of evidence (narration, image description, slide text, keywords) as its own embedded item instead of one long blob of text.
  • Score every ranking idea against labeled questions before keeping it, and drop the ones that lose, even when they felt right.
  • Make each search result explain why it ranked, so you can debug the ranking by looking at it.
  • Push back when an AI agent invents a constraint or keeps adding scope, and switch models when its advice keeps going wrong.

Web app · October 2026

Faculty Twin

Python, FastAPI, Claude, Voyage AI embeddings, ElevenLabs, Supabase, Vercel, Claude Code

An AI version of me that teaches from my own slides. Students ask a course question and get my slides from this semester with a narrated walkthrough in an AI voice made from my recordings, and short clips of me explaining it in class. It is behind a passcode for my students. I built it for Effective Coding with AI (15-113), a Carnegie Mellon course, as Project 2 in Fall 2026.

What it teaches

  • Ground every generated sentence in a source you can point to, and have the system say "not covered" below a threshold instead of guessing.
  • Put safety rules in code, not only in prompts, such as a voice that only reads text the backend signed.
  • De-identify data before it is indexed, and add an automatic leak check, because a pipeline the AI wrote will miss cases.
  • Evaluate answers with AI judges from more than one company, and read their reasoning, not only their scores.
  • Decide which core pieces you write by hand with an AI coach, and let agents build the rest in parallel.

Web app · October 2026

Reels: Me, Over the Years

Python, osxphotos, Apple Vision, OpenCLIP, NumPy, WebGL, Claude Code

172 photos of me from my own photo library, 2000 to 2026, cut two ways. Version 2 is a 3:41 music video drawn live in the browser with WebGL, cut to the beat of a CC0 track in the neon style of K-pop animation. Version 1 is a pair of slideshows: me at work, and me everywhere else. I built it for Effective Coding with AI, a Carnegie Mellon course, as Project 2.

What it teaches

  • Turn a one-paragraph wish into a written build brief with hard rules (privacy, licence, sound only on play) before the AI writes any code.
  • Keep private data on your own machine by choosing local models, like Apple Vision and OpenCLIP, over online services.
  • Add an independent second check when one detector misses things, and still look at every output by eye.
  • Give an AI that cannot listen a way to measure instead: tempo from the kick drum band, song energy printed as a row of text.
  • Make every frame a pure function of the song time, so seeking is exact and the same code can render a video file.

Web app · September 2026

Ignatius at Home

Python, FastAPI, Claude Code, Claude, ElevenLabs, Supabase, Render

A meditation app that turns reading material, such as a handout, a few passages, or just an idea like "seven days on a theme", into a guided audio series listened to one day at a time. Each day pairs a reading with a slow, repeated listening, a short reflection, some background on the text, a stretch of quiet between two bells, and a painting to sit with. I built it for Effective Coding with AI, a Carnegie Mellon course, as the course's server-side project on Render.

What it teaches

  • Write a design spec and build plan before any code, then rebuild against a written revision spec instead of asking for features one at a time.
  • Draw a hard line around what the model may write, and what it must copy word for word from the person's own material.
  • Run an app at no cost to its users by putting open models, free voices and free search tiers behind the same interface as the paid ones.
  • Turn each bug seen on a real phone into a logged prompt, and find the cause the platform imposes, such as timers that stop when the screen turns off.
  • Replace a generic AI-made look with a visual direction taken from the subject, using mockups approved before any CSS is written.

Web app · September 2026

Rink Rivals

Python, Flask, Claude Code, the NHL API, OpenAI

Type in two NHL players and see their careers side by side: every regular-season statistic with the leader highlighted, each player's draft position and trophies, and a season-by-season chart of their production. If you want it settled, a language model reads the whole comparison and picks a winner. It has to commit, explain the pick, and give the strongest argument against it. I built it for Effective Coding with AI, a Carnegie Mellon course, as a study in what a small app owes the person using it.

What it teaches

  • Ask the AI about an API's shape, keys and CORS headers before writing code, and let the answers pick the architecture.
  • Catch a "top result" bug with a test that checks the real endpoint, not just your own code.
  • Decide what an app should refuse to compute when the numbers would be accurate and meaningless.
  • Separate workload statistics from quality statistics so a long career cannot pass for a great one.
  • Keep an API key on the server, and explain why a static host and build-time secrets cannot hold one.

This is the small, public version. I have also built a much larger hockey platform that is now being demonstrated to NCAA Division I programs for their coaches, managers, scouts, and players. Its code and login are private, so they are not linked here. It runs several coordinating agents and a data-analysis agent over a hockey database of more than 6 GB. I am happy to demo it in person for anyone interested in hockey data work at that scale.

Browser game · September 2026

Charlie Road

Kiro, Claude Code, three.js

A browser version of Crossy Road starring Charlie, our nine-year-old cocker spaniel, in place of the chicken. It keeps what makes the original work: the voxel look, one hop per input, endless roads, rivers, and railways, and a camera that punishes dawdling. Then it adds what matters to Charlie: tennis balls instead of coins, a bark that stops traffic, squirrels to chase, his real outfits as unlocks, a giant caterpillar toy worth five balls, and a flying saucer piloted by a squirrel where the eagle used to be.

What it teaches

  • Measure the thing you are copying and put the numbers in the spec, so the AI builds to a target instead of a guess.
  • Write a definition of done a machine can check, then let an autonomous run work until it holds.
  • Build a debug harness that steps the simulation, and verify behavior by asserting on state, not by looking at screenshots.
  • Make the AI log every judgment call it makes on its own, so you can review the choices you did not make.
  • Compare a 30-minute prototype with a planned rebuild to see what a spec actually buys you.

Experiment · September 2026

Can a computer pass an IQ test?

Python, Claude Code, 16 language models

  • 13random guessing
  • 34a student's 2017 program
  • 59expert system, no language model
  • 93current language model

Three programs, one from 2017 and two from this year, take the same 96 Raven's Progressive Matrices, the wordless reasoning test from 1936 that still shows up in hiring. A current language model, given the puzzle sheet and every cell as images, nearly aces it.

What it teaches

  • Run a diagnostic that asks where the bottleneck is before you ask an AI to add more machinery.
  • Check that invented training data looks like the real test, and hold out data the model never saw.
  • Compare AI models on accuracy, cost and time with the same prompt, and let a script generate every number from the raw results.
  • Treat a suspicious zero as a bug in your own code before you blame the model.
  • Steer a coding agent with corrections and challenges to its work, not only with the opening brief.

Browser game · September 2025

Connections About You

JavaScript, Node.js, Express, OpenAI GPT-5 with web search, gpt-oss-120b, Playwright, Claude Code

A word game in the style of the NYT's Connections. An AI writes puzzles about a person: type a name and a town, and GPT-5 searches the web and builds four groups of four from that person's work, their city, and some guesses about their tastes. When the game ends, it explains each group and links to what it read. Next to five puzzles it wrote about me, I added three packs I wrote by hand, for Star Wars, The Lord of the Rings and Carnegie Mellon, each in its own animated theme.

What it teaches

  • Split the work: let the model propose a puzzle, and let code check every rule that code can check.
  • Turn soft goals into numbered limits in the prompt, like "at most one group about work," because a model follows numbers better than adjectives.
  • Show the model real examples of the format instead of describing it, and feed back its recent output so it stops repeating itself.
  • Decide where an API key will live before you design the app, since a static page cannot keep a secret.
  • Write the same kind of content by hand to find out what the AI cannot do yet.
